# motor_control 참고용 코드

비전 자동 추적(`A,dx,dy,flag`)을 받으려면 `firmware/motor_control`에 무엇을 바꾸면 되는지 보여주는 **참고용 수정본**입니다.

- **원본 파일은 고치지 않았습니다.** 이 폴더의 파일은 빌드에 들어가지 않습니다.
- 원본과 나란히 놓고 비교한 뒤, 필요한 부분을 **직접** 옮겨 주세요.
- 바뀐 곳마다 코드 안에 `★ [변경 n]` 표시와 함께 **원래 / 바꾼 것 / 의미**를 주석으로 적었습니다.

## 원본과 다른 점 한눈에 보기

| 표시 | 파일 | 원래 | 바꾼 것 | 의미 |
|---|---|---|---|---|
| ★ [변경 1] | `auto_참고용.cpp` | `HALF_WIDTH = 320`, `HALF_HEIGHT = 240` | `640`, `360` | 320/240은 640×480 화면 기준. 비전은 1280×720이라, 그대로 두면 화면 절반만 벗어나도 최고 속도가 됨 |
| ★ [변경 1] | `main_참고용.cpp` | `auto.h`를 include 안 함 | `#include "auto.h"`, `AUTO_LIMIT = 2000` | `auto_control()`을 부를 수 있게 함. 2000을 넘는 값은 잘못된 값으로 버림 |
| ★ [변경 2] | `main_참고용.cpp` | 없음 | `handle_auto()` 함수 | 받은 시각 기록(기존 0.3초 타임아웃에 사용) → AUTO 모드 전환 → `auto_control()` 호출 |
| ★ [변경 3] | `main_참고용.cpp` | `strcmp(data, "A") == 0`만 있음 (`A` 한 글자만 인식) | `"A,"`로 시작하는 줄을 `sscanf`로 읽는 갈래 추가 | `M,x,y` 읽는 방식과 똑같음. 원래의 `A` 한 글자 처리도 그대로 둠 |

## 비전이 보내는 메시지

```
A,dx,dy,flag\n      예) A,310,20,1  = 드론이 오른쪽 310px, 위 20px에 보임
                        A,0,0,0     = 드론 안 보임
```

- `dx`: 화면 중앙 기준 가로 픽셀. 오른쪽 +, 왼쪽 − (약 −640 ~ +640)
- `dy`: 화면 중앙 기준 세로 픽셀. 위쪽 +, 아래쪽 − (약 −360 ~ +360)
- 정수를 글자로 보냅니다 (2바이트 바이너리 아님). 조이스틱 `M,x,y`와 같은 모양이라 원본 `serial_receive()`를 그대로 쓸 수 있습니다.

## 확인한 것

- 참고용 두 파일을 원본 대신 넣고 PlatformIO 빌드에 성공했어요 (RAM 21%, Flash 30%).
- `main_참고용.cpp`에 원본 217줄이 순서 그대로 전부 들어 있는 것도 확인했어요. 추가만 했다는 뜻입니다.
- `auto_참고용.cpp`는 원본과 `HALF_WIDTH`, `HALF_HEIGHT` 두 줄만 다른 것도 확인했어요.
- 실제 모터를 돌려 보는 시험은 아직 못 했습니다.

## 시리얼 모니터로 시험하기 (115200 baud, 줄바꿈 LF)

| 입력 | 기대 결과 |
|---|---|
| `A,320,0,1` | 오른쪽으로 천천히 (약 12 RPM) |
| `A,640,0,1` | 오른쪽으로 최고 속도 |
| `A,0,360,1` | 위로 최고 속도 |
| `A,100,0,1` | 안 움직임 (0.4 RPM → 반올림 0) |
| `A,0,0,0` | 정지 |

아무것도 안 보내면 0.3초 뒤 IDLE로 바뀌어 멈춥니다(원본의 타임아웃 기능). 계속 움직이게 하려면 같은 줄을 반복해서 보내야 합니다.

자세한 배경은 [`docs/serial-integration-report.md`](../../serial-integration-report.md)를 참고하세요.
