## 2. 왜 이렇게 바꿨나

### 2.1 핵심 요약

> **팀 펌웨어를 기준으로 맞추고, 비전이 따라갔습니다.** 팀원이 이미 만든 F1/F2/F3 구조, `A,dx,dy,flag` 형식, 3제곱 속도 곡선, 0.3초 안전 정지를 모두 그대로 살렸습니다. 팀 펌웨어에 제안하는 변경도 기존 코드는 **숫자 2개**와 **TODO 자리**뿐이고, 나머지는 빠져 있던 연결을 **추가**하는 것입니다.

### 2.2 이유 하나씩

**① 팀원 코드를 최대한 그대로 쓰기 위해**

`control.py`에는 이미 F3을 누르면 `A,{deltaX},{deltaY},{flag}`를 보내는 코드가 있었고, `auto.cpp`에는 속도 계산이 있었습니다. 비어 있던 건 "비전 값 받기"(TODO)와 "`A,` 메시지 읽기" 두 군데뿐이었습니다. 그래서 새로 만들기보다 그 두 곳을 채우는 게 가장 작은 변경입니다.

| 파일 | 기존 코드 변경 | 추가 |
|---|---|---|
| `auto.cpp` | 숫자 2개 (320 → 440, 240 → 285) | 주석 |
| `main.cpp` | 없음 | `A,dx,dy,flag` 읽기, `handle_auto()` |
| `control.py` | TODO 함수 내용 | UDP로 비전 값 받기 |

**② COM 포트는 프로그램 하나만 열 수 있어서**

전에 만든 비전 코드는 COM 포트를 직접 열고 아두이노로 보냈습니다. 그런데 `control.py`도 같은 포트를 엽니다. 둘을 동시에 켜면 나중에 켠 쪽이 에러로 꺼집니다. 그래서 **포트는 `control.py`만 열고**, 비전은 같은 PC 안에서 **UDP로 값만 넘겨주는** 구조로 바꿨습니다. 이렇게 하면 F1/F2/F3 전환도 그대로 쓸 수 있습니다.

**③ 픽셀로 보내면 해상도에 따라 반응이 2배로 틀어져서**

기존 `auto.cpp`는 `dx / 320`, `dy / 240`으로 나눕니다. **640×480 화면**을 가정한 숫자입니다. 그런데 비전은 **1280×720**으로 돌립니다(카메라 기본 비율, 더 선명함). 이 상태에서 픽셀 오차를 그대로 보내면 이렇게 됩니다.

| 드론 위치 | 1280×720에서 dx | `dx / 320` | 결과 |
|---|---|---|---|
| 화면 1/4 지점 | 320 | 1.0 | **벌써 최고 속도** |
| 화면 끝 | 640 | 2.0 → 1.0으로 잘림 | 최고 속도 |

화면 절반 지점부터 이미 최고 속도라서, 가까울 때 살살, 멀 때 빠르게 움직이는 3제곱 곡선이 제대로 작동하지 않습니다. **각도 × 10**으로 보내고 440/285로 나누면 해상도를 바꿔도(640, 1280, 1920) 화면 끝이 항상 ±1.0입니다. 카메라를 바꿔도 비전 쪽 화각 값(`--dfov`) 하나만 고치면 되고, 펌웨어는 그대로 둘 수 있습니다.

**④ 방향(부호)을 조이스틱과 같게 해서**

조이스틱 모드에서는 스틱을 **위로 밀면 y가 +**입니다(`control.py`: `y = -axis(1) * 1200`). `auto.cpp`도 같은 공식을 씁니다. 그런데 영상 좌표는 **아래가 +**입니다. 그대로 보내면 드론이 아래에 있을 때 카메라가 위로 올라가서 드론을 놓칩니다. 그래서 비전 쪽에서 **dy를 위쪽 +로 뒤집어서** 보냅니다. 결과적으로 "조이스틱으로 확인한 방향 = 자동 모드 방향"이 되어, 방향 확인을 조이스틱으로 한 번만 하면 됩니다.

**⑤ 끊기거나 오래된 값으로 모터가 움직이지 않게**

| 단계 | 안전장치 |
|---|---|
| 비전 | 드론이 안 보여도 매 프레임 `0,0,0`을 보냄 (하트비트) |
| `control.py` | 비전 값이 **0.3초** 넘게 안 오면 `0,0,0`으로 처리 |
| `control.py` | 다른 모드에 있다가 F3으로 들어오면, **그동안 쌓인 오래된 값은 버림** |
| `main.cpp` | 각도가 ±90°를 넘거나 형식이 이상하면 그 메시지는 버림 |
| `main.cpp` | 기존 기능 그대로: **0.3초** 동안 메시지가 없으면 대기 모드로 바꾸고 모터 정지 |

`control.py`와 `main.cpp` 줄 중 0.3초 정지를 뺀 나머지는 제안 패치에 들어 있습니다. 세 번째 줄은 시험하다가 발견한 문제를 막으려고 넣었습니다. 키보드 모드를 쓰는 동안 쌓여 있던 예전 비전 값이, F3을 누른 순간 "방금 받은 값"으로 잘못 쓰일 수 있었습니다.

**⑥ 글자(ASCII)로 통일한 이유**

`control.py`와 `main.cpp`가 이미 글자 한 줄 단위(`P,w`, `M,x,y`)로 주고받습니다. 여기에 int16 바이너리를 섞으면 숫자 10이 줄바꿈 코드(0x0A)와 같아서, **특정 값에서만 가끔 메시지가 잘리는** 찾기 힘든 버그가 생깁니다. 속도 차이도 약 0.6ms로, 카메라·YOLO 지연(수십~100ms)에 비하면 1% 미만입니다. 참고로 `control.py`의 TODO 주석에 있던 "int16"은 **정수 값**을 달라는 뜻으로 보고, 정수로 넘기도록 했습니다.

### 2.3 검토했지만 고르지 않은 방법

| 방법 | 고르지 않은 이유 |
|---|---|
| 비전이 아두이노로 직접 전송 (예전 `<flag,ax,ay>` 방식) | COM 포트 충돌로 `control.py`와 동시 사용 불가. 키보드·조이스틱 모드를 못 씀 |
| 별도 아두이노 스케치(`pan_tilt_tracker`) 사용 | 팀 펌웨어와 같은 일을 하는 중복 코드. 그래서 **삭제**함 |
| 픽셀 오차 전송 | 해상도마다 반응이 달라짐 (③) |
| int16 바이너리 | 기존 글자 형식과 섞이면 버그, 속도 이득은 거의 없음 (⑥) |
| 비전과 `control.py`를 한 프로그램으로 합치기 | 두 코드가 다른 저장소에 있고 담당자도 다름. 나중에 원하면 가능 |

### 3.1 비전 → `control.py` (UDP, 같은 PC 안)

|---|---|
| 주소 | `127.0.0.1:5005` (같은 PC) |
| 내용 | `dx,dy,flag` (글자, 줄바꿈 없음) |
| 주기 | 카메라 프레임마다 (약 15~30번/초) |
| 받는 쪽이 없을 때 | 비전은 에러 없이 계속 동작 |

### 3.2 `control.py` → 아두이노 (USB 시리얼, 기존 그대로)

| 항목 | 값 |
|---|---|
| 속도 | 115200 baud |
| 주기 | 20번/초 (`control.py` 기존 설정) |
| F3 자동 모드 메시지 | `A,dx,dy,flag\n` |

### 3.3 값의 뜻

| 값 | 뜻 | 범위 |
|---|---|---|
| `dx` | 화면 중앙에서 가로로 몇 도 벗어났나 × 10. **오른쪽이 +** | 약 −440 ~ +440 (화면 끝 ±44.0°) |
| `dy` | 화면 중앙에서 세로로 몇 도 벗어났나 × 10. **위쪽이 +** | 약 −285 ~ +285 (화면 끝 ±28.5°) |
| `flag` | 드론이 보이나 | 1 = 보임, 0 = 안 보임 (이때 dx, dy는 0) |

**예시**

| 아두이노가 받는 메시지 | 뜻 | 모터 |
|---|---|---|
| `A,0,0,1` | 드론이 정확히 가운데 | 정지 (데드밴드) |
| `A,250,17,1` | 오른쪽 25.0°, **위** 1.7° | 오른쪽으로 약 18 RPM (3제곱 곡선: 0.57³ × 100), 위로는 거의 0 |
| `A,-440,-285,1` | 왼쪽 끝, 아래쪽 끝 | 왼쪽 아래로 최고 속도 |
| `A,0,0,0` | 드론 안 보임 | 정지 |

## 4. 동작 원리 (쉽게)

### 4.1 PC와 아두이노는 어떻게 대화하나

USB 케이블로 **글자를 한 글자씩** 보냅니다. 케이블에는 각 글자의 번호(ASCII 코드)가 흐릅니다. 예를 들어 `A`=65, `,`=44, `2`=50입니다. 아두이노는 도착한 글자를 64글자짜리 임시 보관함(수신 버퍼)에 쌓아 두고, 줄바꿈(`\n`)이 올 때까지 모은 다음 숫자로 바꿉니다. 양쪽은 **1초에 115200비트(115200 baud)**라는 속도를 미리 맞춰 둡니다.

### 4.2 "각도 × 10"의 뜻

25.0°처럼 소수점이 있는 값은 아두이노 Uno에서 읽기 번거로워서, **각도에 10을 곱한 정수**를 보냅니다. 25.03°라면 250입니다. 3.50달러를 350센트라고 쓰는 것과 같습니다.

> 0.1°까지 정확하다는 뜻은 **아닙니다.** YOLO 박스가 프레임마다 몇 픽셀씩 흔들려서 실제 정확도는 대략 ±0.5°입니다. 10을 곱하는 건 정수로 보내기 위한 표기 방법일 뿐입니다.

### 4.3 픽셀을 각도로 바꾸는 방법 (atan)

직각삼각형에서 `tan(각도) = 높이 ÷ 밑변`이고, 반대로 높이와 밑변으로 각도를 구하는 함수가 `atan`입니다.

```
   화면(센서)
   ┌────────────────●──────┐   ← 드론: 중앙에서 오른쪽으로 310픽셀
   │        중앙 ●───┘ 310px │
   └────────────┬───────────┘
                │ f = 663.5px   ← 렌즈~화면 거리를 픽셀 단위로 나타낸 값(초점거리)
              렌즈

   각도 = atan(310 ÷ 663.5) = 25.0°
```

f는 "화면 모서리의 각도 = 대각 화각의 절반"이라는 걸 이용해 구합니다. 우리 카메라(STCOM biz FHD60F)는 대각 화각이 95.8°입니다.

```
1280×720에서 중앙~모서리 = √(1280² + 720²) ÷ 2 = 734.3px
f = 734.3 ÷ tan(95.8° ÷ 2) = 663.5px
```

비례식(310/640 × 44° = 21.3°)으로 계산하면 **약 4° 틀립니다.** 화면 바깥쪽일수록 1°에 더 많은 픽셀이 들어가기 때문입니다.

**확인한 것:** 이 계산으로 나오는 가로·세로 화각(88.0°, 57.0°)이 제조사 스펙(88.4°, 57.6°)과 0.5° 안쪽으로 맞습니다. 1280×720과 1920×1080에서 화면이 잘리지 않는 것도 실측으로 확인했습니다.

나머지(데드밴드, 3제곱 곡선, 속도 제한, `rpm2 = pan + tilt`)는 **그대로**입니다. `DEADBAND = 10`은 이제 "1.0° 안쪽 오차 무시"라는 뜻이 됩니다.

### 5.2 `Core/Src/main.cpp` — 추가만

```cpp
#include "auto.h"
const int AUTO_LIMIT = 900;   // ±90° 넘으면 잘못된 값

void handle_auto(int dx, int dy, int flag) {
    last_rx = millis();
    set_mode(AUTO);
    if (stop_pending) return;              // 모드 바꾼 직후엔 정지 명령부터
    if (!auto_control(dx, dy, flag)) request_stop();
}

// process_command() 안에 추가
else if (strncmp(data, "A,", 2) == 0) {
    int dx, dy, flag; char extra;
    if (sscanf(data + 2, "%d,%d,%d%c", &dx, &dy, &flag, &extra) == 3) {
        if (범위 밖이거나 flag가 0/1이 아니면) return;
        handle_auto(dx, dy, flag);
    }
}
```

`M,x,y`를 읽는 기존 코드와 같은 방식(`sscanf`, 범위 검사)으로 썼습니다. 기존의 `A` 한 글자 명령도 그대로 남겨 두었습니다.

## 6. 실행 방법

```powershell
# 0) 제안 패치 적용 (저장소 최상위 폴더, 한 번만)
git apply docs/proposals/motor_control_auto_mode.patch

# 1) 아두이노에 펌웨어 올리기 (motor_control 폴더, PlatformIO)
pio run -t upload

# 2) control.py 실행 (COM 번호는 control.py 안의 "COM7"을 실제 포트로)
python control.py

# 3) 비전 실행 (uav-tracker-test 폴더)
```

| 용어 | 뜻 |
|---|---|
| 시리얼 통신 | 데이터를 한 비트씩 차례로 보내는 방식. 여기서는 USB 케이블로 함 |

| UDP | 같은 PC나 네트워크 안에서 짧은 데이터를 주고받는 간단한 방법. 여기서는 비전 → control.py |
| 하트비트 | "연결되어 있음"을 알리려고 주기적으로 보내는 신호 |

| 초점거리 f | 렌즈에서 화면까지 거리. 여기서는 픽셀 단위(663.5px)로 씀 |
| atan | 직각삼각형의 높이와 밑변으로 각도를 구하는 함수 |
| 데드밴드 | 이 값보다 작은 오차는 무시하는 구간. 중앙 근처 떨림 방지 |
| PlatformIO | VS Code에서 쓰는 임베디드 개발 도구. 아두이노 IDE 대신 `.cpp`/`.h` 파일로 개발 |
| CAN | 여러 장치를 두 가닥 선으로 연결하는 통신 방식. 아두이노에서는 MCP2515 모듈 사용 |
| MKS SERVO42D | NEMA17 스텝모터 + 엔코더 + FOC 폐루프 드라이버. 이름과 달리 RC 서보가 아님 |
| YOLO / ByteTrack | YOLO는 영상에서 물체를 찾는 AI, ByteTrack은 같은 물체에 같은 번호(ID)를 붙이는 추적기 |
