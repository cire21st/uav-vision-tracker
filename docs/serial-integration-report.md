## 2. 요청 반영 내역

| # | 요청 | 반영 | 알아둘 점 |
|---|---|---|---|
| 1 | `control.py`를 거치지 않고 **바로 보내기** | 비전이 COM 포트를 직접 열고 아두이노로 보냄 | ⚠️ **조이스틱 프로그램(`control.py`)과 동시에 쓸 수 없습니다** |
| 2 | **int16(정수)**로 보내기 | dx, dy, flag 모두 **정수** | 형식은 **조이스틱(`M,x,y`)과 통일**해서 정수를 글자로 보냄. 같은 수신 코드로 읽을 수 있음 (2.2) |
| 3 | 각도 말고 **error x, error y** | 화면 중앙 기준 **픽셀 오차** | 비전은 **1280×720** 기준. `auto.cpp`의 320/240을 **640/360**으로 바꿔 주세요 |
| 4 | (추가) 방향 | **xy 평면처럼** 오른쪽 +, **위쪽 +** | 조이스틱 모드와 같은 방향이라 `auto.cpp` 부호는 그대로 |

### 2.1 조이스틱 프로그램과 동시에 못 쓰는 이유

COM 포트는 **한 번에 프로그램 하나만** 열 수 있습니다. 비전이 아두이노 포트를 직접 열면, 같은 포트를 쓰는 `control.py`(키보드·조이스틱)는 열리지 않습니다. 반대도 마찬가지입니다.

- 자동 추적을 할 때: `control.py`를 끄고 비전을 켭니다.
- 조이스틱으로 조종할 때: 비전을 끄고 `control.py`를 켭니다.

### 2.2 형식은 조이스틱과 통일했습니다

보내는 값은 요청대로 **정수**입니다. 그리고 메시지 모양은 조이스틱 메시지 `M,x,y`와 **똑같은 방식**(글자 + 쉼표, 한 줄)으로 맞췄습니다.

```
조이스틱:  M,850,-300      ← 이미 펌웨어가 읽고 있는 형식
비전:      A,310,20,1      ← 같은 모양
```

**왜 통일했나:** 펌웨어의 `serial_receive()`는 이미 글자를 줄 단위로 모으고, `process_command()`가 첫 글자(`P` / `M` / `I`)를 보고 나눠서 처리합니다. 비전도 같은 모양으로 보내면 **수신 코드를 새로 짤 필요 없이** `process_command()`에 `A,` 한 갈래(약 15줄)만 추가하면 됩니다. 입력 받는 코드를 두 번 짜지 않아도 되고, 모든 입력이 한 가지 규칙으로 통일됩니다.

**정 2바이트 바이너리(int16)를 원하면 다시 짜 드리겠습니다.** 다만 두 방식을 비교하면 이렇습니다.

| | 지금 방식 (글자, 조이스틱과 통일) | 바이너리 방식 (2바이트 int16) |
|---|---|---|
| 펌웨어 수신 코드 | 기존 코드 그대로 사용. `A,` 갈래만 추가 (`M,x,y`와 같은 `sscanf`) | **수신 코드를 따로 하나 더** 짜야 함: 시작 바이트 찾기, 바이트 모으기, 체크섬 확인, 2바이트를 숫자로 조립 |
| 조이스틱 메시지와 함께 받을 때 | 같은 규칙이라 문제없음 | 값이 10, 266, −246 등일 때 그 안의 바이트 `0x0A`가 줄바꿈으로 오인돼 **가끔 메시지가 잘림**. 피하려면 수신부 구조를 바꿔야 함 |
| 테스트·디버깅 | 시리얼 모니터에 `A,310,20,1`이 그대로 보이고, 손으로 입력해서 시험 가능 | 깨진 글자로 보여서 눈으로 확인 불가. 테스트용 프로그램이 따로 필요 |
| 메시지 길이 | 11~14바이트 | 8바이트 |
| 전송 시간 (115200 baud) | 약 1.2ms | 약 0.7ms |
| 실제 체감 차이 | — | 약 0.5ms 빠름. 카메라·YOLO 지연(수십~100ms)에 비하면 **1% 미만** |

정리하면, 바이너리로 바꿔서 얻는 건 0.5ms 정도입니다. 반면 수신 코드를 한 벌 더 짜야 하고, 조이스틱 메시지와 섞일 때 가끔 깨지는 버그를 막을 장치도 필요합니다.

> 지금 방식으로 갈 때 주의할 점: 받는 쪽에서 2바이트씩 읽도록 짜면 값을 하나도 못 읽습니다. `M,x,y`를 읽는 코드와 똑같이 `sscanf`로 읽으면 됩니다.

### 2.3 해상도 숫자를 바꿔야 하는 이유

`auto.cpp`는 오차를 **화면 절반 크기**로 나눠 −1~+1로 만든 뒤 속도를 정합니다. 지금 숫자 320/240은 **640×480** 기준인데, 비전은 **1280×720**으로 돕니다(카메라 기본 비율 16:9, 화면 잘림 없음 확인). 숫자를 그대로 두면 이렇게 됩니다.

| 드론 위치 (1280×720) | dx | `dx / 320` | `dx / 640` |
|---|---|---|---|
| 중앙과 오른쪽 끝의 중간 | 320 | 1.0 → **벌써 최고 속도** | 0.5 → 약 12% 속도 |
| 오른쪽 끝 | 640 | 2.0 → 1.0으로 잘림 | 1.0 → 최고 속도 |

그래서 **640/360**으로 바꿔야 3제곱 곡선(가까우면 살살, 멀면 빠르게)이 의도대로 동작합니다.

> 비전 해상도를 바꾸면(`--width`, `--height`) 이 숫자도 같이 바꿔야 합니다. 기본값 1280×720을 그대로 쓰면 신경 쓸 필요 없습니다.

### 2.4 방향: xy 평면

| | 오른쪽 | 왼쪽 | 위쪽 | 아래쪽 |
|---|---|---|---|---|
| dx | + | − | | |
| dy | | | **+** | **−** |

영상 좌표는 원래 아래쪽이 +지만, 비전이 세로 부호를 뒤집어서 **수학의 xy 평면과 같게** 보냅니다. 팀 조이스틱 코드도 스틱을 위로 밀면 +(`control.py`: `y = -axis(1) * 1200`)라서 방향이 같습니다. 그래서 **조이스틱 모드에서 방향을 한 번 확인하면 자동 모드도 같은 방향**으로 움직입니다.

## 3. 메시지 규칙

| 항목 | 값 |
|---|---|
| 연결 | USB 시리얼, 115200 baud |
| 형식 | `A,dx,dy,flag` + 줄바꿈(`\n`), 글자 한 줄 |
| 주기 | 카메라 프레임마다 (약 15~30번/초) |
| 연결 직후 | 비전이 2초 기다린 뒤 전송 시작 (Uno는 포트가 열리면 재부팅됨) |

| 값 | 뜻 | 범위 (1280×720) |
|---|---|---|
| `dx` | 화면 중앙에서 가로로 몇 픽셀. **오른쪽 +** | 약 −640 ~ +640 |
| `dy` | 화면 중앙에서 세로로 몇 픽셀. **위쪽 +** | 약 −360 ~ +360 |
| `flag` | 1 = 드론 보임, 0 = 안 보임 (이때 dx, dy는 0) | 0 / 1 |

**예시** (640/360으로 바꾼 뒤 기준)

| 메시지 | 뜻 | 모터 |
|---|---|---|
| `A,0,0,1` | 드론이 정확히 가운데 | 정지 |
| `A,310,20,1` | 오른쪽 310px, 위 20px | 오른쪽으로 약 11 RPM (0.48³ × 100), 위로는 거의 0 |
| `A,-640,-360,1` | 왼쪽 끝, 아래쪽 끝 | 왼쪽 아래로 최고 속도 |
| `A,0,0,0` | 드론 안 보임 | 정지 |

**끊김 처리**
- 드론이 안 보여도 비전은 매 프레임 `A,0,0,0`을 보냅니다(하트비트). 그래서 "드론 놓침"과 "비전 꺼짐"을 구분할 수 있습니다.
- 비전이 꺼지면 메시지가 끊기고, 펌웨어에 이미 있는 **0.3초 타임아웃**으로 대기 모드가 되어 모터가 멈춥니다.
- 비전을 정상 종료할 때는 마지막으로 `A,0,0,0`을 보냅니다.

### 왜 바꿔야 하나

지금 펌웨어는 정확히 `A` 한 글자만 알아들어서 `A,310,20,1`은 무시됩니다. 또 `auto.cpp`의 `auto_control()`은 만들어져 있지만 아무 곳에서도 부르지 않습니다.

### 원본과 다른 점

| 표시 | 파일 | 원래 | 바꾼 것 | 의미 |
|---|---|---|---|---|
| ★ [변경 1] | `auto_참고용.cpp` | `HALF_WIDTH = 320`, `HALF_HEIGHT = 240` | `640`, `360` | 1280×720 화면의 절반. 화면 끝에서 ±1.0이 되게 함 (2.3) |
| ★ [변경 1] | `main_참고용.cpp` | `auto.h` include 안 함 | `#include "auto.h"`, `AUTO_LIMIT = 2000` | `auto_control()`을 부를 수 있게 함. 2000 넘는 값은 버림 |

### 핵심 코드 (전체는 참고용 파일 참고)

```cpp
// auto_참고용.cpp — ★ [변경 1]
const float HALF_WIDTH = 640.0f;   // 원래 320
const float HALF_HEIGHT = 360.0f;  // 원래 240
```

```cpp
// main_참고용.cpp — ★ [변경 2]
void handle_auto(int dx, int dy, int flag) {
    last_rx = millis();
    set_mode(AUTO);
    if (stop_pending) return;              // 모드 바꾼 직후엔 정지 명령부터
    if (!auto_control(dx, dy, flag)) request_stop();
}

// main_참고용.cpp — ★ [변경 3] (process_command() 안, 기존 "A" 처리 위)
else if (strncmp(data, "A,", 2) == 0) {
    int dx, dy, flag; char extra;
    if (sscanf(data + 2, "%d,%d,%d%c", &dx, &dy, &flag, &extra) == 3) {
        // 범위 밖이거나 flag가 0/1이 아니면 버림
        handle_auto(dx, dy, flag);
    }
}
```

## 5. 동작 원리 (쉽게)

USB 케이블로 **글자를 한 글자씩** 보냅니다. `A,310,20,1`이라면 케이블에는 각 글자의 번호(ASCII 코드)가 차례로 흐릅니다.

```
글자:  A   ,   3   1   0   ,   2   0   ,   1   \n
번호: 65  44  51  49  48  44  50  48  44  49  10
```

아두이노는 도착한 글자를 64글자짜리 임시 보관함(수신 버퍼)에 쌓아 두고, 줄바꿈(10)이 오면 한 줄을 꺼내 `sscanf`로 숫자 `310`, `20`, `1`로 바꿉니다. 양쪽은 **1초에 115200비트(115200 baud)**라는 속도를 미리 맞춰 둡니다.

## 6. 실행 방법

```powershell
# 1) 아두이노에 펌웨어 올리기 (firmware/motor_control 폴더, PlatformIO)
pio run -t upload

# 2) control.py, 시리얼 모니터 등 같은 COM 포트를 쓰는 프로그램은 모두 닫기

# 3) 비전 실행 (uav-tracker-test 폴더)
.\.venv\Scripts\python.exe main.py --serial auto     # 아두이노 자동으로 찾기
.\.venv\Scripts\python.exe main.py --serial COM7     # 또는 포트 직접 지정
```

- 비전 콘솔에 나오는 JSON의 `sent` 항목에서 마지막으로 보낸 메시지를 볼 수 있습니다.
- `auto`는 연결된 아두이노가 딱 하나일 때만 자동으로 잡습니다. 못 찾으면 포트 목록을 보여주고 끝나니, 그중 하나를 직접 지정하세요.

## 부록: 용어 풀이

| 용어 | 뜻 |
|---|---|
| 시리얼 통신 | 데이터를 한 비트씩 차례로 보내는 방식. 여기서는 USB 케이블로 함 |
| baud | 1초에 보내는 비트 수. 115200 baud = 1초에 115200비트 |
| ASCII | 글자마다 번호를 붙인 표. `A`=65, `0`=48, 줄바꿈=10 |
| COM 포트 | 윈도우가 시리얼 장치에 붙이는 이름 (COM3, COM7 등). 한 번에 한 프로그램만 열 수 있음 |
| 하트비트 | "연결되어 있음"을 알리려고 주기적으로 보내는 신호 |
| 데드밴드 | 이 값보다 작은 오차는 무시하는 구간. 중앙 근처 떨림 방지 |
| PlatformIO | VS Code에서 쓰는 임베디드 개발 도구. 아두이노 IDE 대신 `.cpp`/`.h` 파일로 개발 |
| CAN | 여러 장치를 두 가닥 선으로 연결하는 통신 방식. 아두이노에서는 MCP2515 모듈 사용 |
| MKS SERVO42D | NEMA17 스텝모터 + 엔코더 + FOC 폐루프 드라이버. 이름과 달리 RC 서보가 아님 |
| YOLO / ByteTrack | YOLO는 영상에서 물체를 찾는 AI, ByteTrack은 같은 물체에 같은 번호(ID)를 붙이는 추적기 |
